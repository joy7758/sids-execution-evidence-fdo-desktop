# M1：运行结果收件箱 + 最近结果自动发现

## 目标

M1 的目标是把桌面版的默认入口从“手动导入一个运行结果目录”推进为“先检查运行结果收件箱，再优先使用最近一次完整运行结果”。

这一阶段的重点不是增加更多功能，而是把已有的目录识别能力收进平台主路径，让用户打开软件后先看到“有没有最近可用结果”，而不是先看到文件选择。

## 默认收件箱路径

默认收件箱路径固定为：

- `~/AgentEvidence/runs/`

当前阶段只检查这一处，不做全盘扫描，不做多位置搜索。

## 自动发现规则

M1 的自动发现规则如下：

1. 先判断默认收件箱是否存在
2. 如果存在，只枚举收件箱的一级子目录
3. 不递归扫描更深层目录
4. 对每个一级子目录复用现有运行结果识别逻辑
5. 从“完整运行结果目录”中选最近修改时间的一个，作为“最近一次完整运行结果”

## 完整运行结果定义

完整运行结果目录至少需要识别出：

- bundle（证据包）
- receipt（校验回执）
- summary（摘要）

以下附属文件仍然是可选：

- manifest
- public key
- runtime events

private key（私钥）不参与自动发现，不在界面中作为常规输入展示，也不会传给 sidecar。

## 找不到收件箱时的行为

如果默认收件箱不存在，首页应显示：

- 尚未发现运行结果收件箱
- 默认路径是 `~/AgentEvidence/runs/`
- 用户仍然可以直接选择一个运行结果目录

这时产品仍然可用，只是不会进入“最近结果自动发现”路径。

## 找到不完整目录时的行为

如果收件箱存在，但没有任何完整运行结果：

- 首页显示“未找到可用运行结果”
- 不自动把不完整目录当成默认结果
- 引导用户手动选择一个目录继续
- 如有必要，再切换到高级手动模式修正文件路径

## 与高级手动模式的关系

高级手动模式仍然保留，但在 M1 中继续作为次级入口。

它主要用于：

- 自动识别未完成时补齐缺失文件
- 技术人员临时替换自动识别出的路径
- 处理非标准目录结构

普通用户的默认路径应当是：

- 先看系统是否已经找到最近结果
- 找到就直接进入生成审阅包的流程
- 没找到时再选目录

## 手工验证建议

建议至少覆盖以下场景：

1. 收件箱存在且有完整结果
   - 首页显示“已找到最近一次运行结果”
   - 可以直接进入 Inputs / Build / Result

2. 收件箱存在但结果不完整
   - 首页显示“未找到可用运行结果”
   - 继续按钮转为“选择运行结果目录”

3. 收件箱不存在
   - 首页显示默认收件箱路径
   - 用户仍可继续选择目录

4. 最近结果进入 Build -> Result
   - 自动发现结果可继续到 Build
   - 审阅包成功生成

5. private key 默认排除
   - 自动发现不识别 private key
   - sidecar 输入不包含 private key

## 不做什么

M1 明确不做：

- Windows
- 签名 / 公证
- 云端 / 账号 / 同步
- provider-running UI
- 多来源自动接入
- 全盘目录扫描
- 完整运行列表
- 运行详情页
- 政策检查项展示

这些内容属于后续阶段，不在 M1 范围内。
