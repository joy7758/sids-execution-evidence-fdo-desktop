# M2：运行列表 + 状态卡片

## 目标

M2 的目标，是把首页从“只盯住最近一次运行”升级成“先看最近几次运行，再决定使用哪一次继续”。这一层仍然只服务于当前平台主线：运行监测、留痕与审阅交付。

## 运行列表显示规则

- 数据来源仍然只使用 `~/AgentEvidence/runs/`
- 只扫描收件箱的一级子目录
- 不做全盘扫描
- 不递归更深层目录
- 默认只展示最近几条运行，当前版本显示最近 5 条
- 列表按修改时间倒序排列，最新运行始终排在最上面

## 状态卡片最小字段

每张运行卡片至少展示：

- 运行时间
- 运行编号或目录名
- 运行结果目录
- 状态摘要
- 回执状态
- 审阅包状态
- 主动作

当前卡片只做“够用的状态表达”，不引入复杂图表或运维式监控面板。

## 最近一次与手动改选的关系

- 系统仍然默认选中最近一次可用运行
- 用户可以从“最近运行”列表中改选其他一次运行
- 一旦改选，后续 Inputs / Build / Result 流程就跟随该次运行
- 这意味着“最近一次”只是默认入口，不再是唯一入口

## 为什么这一层先不做大图表

M2 的重点，是让用户先判断“哪次运行可继续、哪次需要处理、哪次已经生成过审阅包”。在这个阶段，卡片和简明状态比图表更直接，也更适合中国客户的第一屏理解。

## M2 与 M3 的边界

M2 只解决：

- 最近运行列表
- 状态卡片
- 从列表切换当前运行

M3 再处理真正的“运行详情页”，包括更完整的证据完整性、校验状态、文件级细节和后续操作入口。

## 最小手工验证建议

- 在收件箱中准备多条运行结果目录
- 确认首页能展示“最近运行”列表，且按时间倒序排列
- 确认点击某张卡片后，当前运行会切换到该次运行
- 确认切换后的运行仍可继续进入 Build / Result
- 确认首页主状态区和最近运行列表的关系清晰：主状态负责默认入口，列表负责比较与改选
