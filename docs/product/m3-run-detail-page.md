# M3：运行详情页

## 目标

M3 的目标，是让用户从“首页能看到最近运行状态”进一步走到“点开某次运行后，能一眼看清这次运行到底缺什么、能不能继续、下一步该做什么”。

## 详情页最小信息结构

详情页第一版至少包含这些部分：

- 顶部摘要
  - 运行编号
  - 来源
  - 时间
  - 当前状态
- 证据完整性
  - 证据包文件
  - 校验回执文件
  - 摘要文件
- 附属文件
  - manifest
  - public key
  - runtime events
- 当前判断
  - 可生成审阅包
  - 需处理
  - 需人工复核
  - 已生成审阅包
- 下一步动作
  - 生成审阅包
  - 重新选择目录
  - 高级手动修正
  - 返回最近运行

## 详情页与首页的关系

- 首页负责最近运行列表和快速状态判断
- 详情页负责把某次运行的状态、缺项和下一步动作讲清楚
- 首页不做空，详情页也不替代首页

## 详情页与 Build / Result 的关系

- 详情页不是终点，而是进入 Build / Result 之前的判断层
- 完整运行可以从详情继续进入生成前确认
- 不完整运行则从详情进入修正路径
- Result 页继续保持 PDF 第一交付物的逻辑，不在 M3 改动

## 第一屏出现什么，后置什么

第一屏先出现：

- 当前状态
- 缺少什么
- 能不能继续
- 下一步动作

后置的信息：

- 完整文件路径
- 技术文件细节
- 调试式展开内容

## M3 明确不做什么

- 不做大图表
- 不做复杂筛选
- 不做平台级统计页
- 不做运维监控风格的大屏
- 不做新的云端或账号能力

## 最小手工验证建议

- 从最近运行列表进入某次运行详情
- 验证完整运行详情可以继续进入生成前确认
- 验证不完整运行详情会明确显示缺项和修正路径
- 验证详情页第一屏不被完整技术路径压满
