# U1 桌面端客户友好度收敛说明

## 1. U1 目标

U1 不扩产品功能，只收桌面端现有体验。

这一轮只解决三件事：

- 让首页更像中国客户看得懂的软件
- 让状态、动作、细节三层关系更清楚
- 让结果页第一屏先突出交付结果，而不是技术文件

## 2. 首页原则

首页只回答一个问题：

- 系统有没有已经发现可用运行结果

首页第一屏只保留一个主动作：

- 找到结果时：生成审阅包
- 没找到结果时：导入运行结果

“查看详情”只能是次级入口，高级手动选择放到更后面。

## 3. 状态优先原则

每一页都先让用户看到状态，再决定要不要展开细节。

默认优先级应当是：

1. 当前状态
2. 当前可做的动作
3. 需要处理的问题
4. 技术文件与路径详情

这意味着 `bundle / receipt / summary` 不能再作为第一屏的主要视觉内容。

## 4. 中文优先原则

这一轮界面收敛默认采用中文主导：

- 主标题用中文
- 主按钮用中文
- 主状态用中文
- 技术词只作为括号辅助

客户可见层统一使用：

- 运行结果
- 运行结果收件箱
- 证据包文件
- 校验回执文件
- 摘要文件
- 审阅包

## 5. 默认路径与高级模式

默认路径必须始终是：

- 自动发现最近运行结果
- 自动判断是否完整
- 直接进入生成路径

高级模式保留，但它的职责只包括：

- 自动识别不完整时修正路径
- 技术人员临时补文件
- 排查少量非标准目录

高级模式不应再与默认路径平级。

## 6. 结果页第一屏只突出什么

结果页第一屏只强调：

- 审阅包已生成
- 保存位置
- 打开文件夹
- 复制路径

下面这些内容默认折叠到“查看输出详情”之后：

- `index.json`
- `report.md`
- 主文件路径
- supporting files 路径

## 7. 本轮不处理什么

U1 明确不处理：

- 中文报告正文
- PDF 导出
- Windows
- 签名 / 公证
- 云端 / 账号 / 同步
- provider-running UI
