# 桌面端用户友好 UI 设计方案 v0.1

## 1. 目标

本设计方案用于把当前桌面端从“功能已经可用”进一步收敛成“非技术用户第一眼能理解、能操作、能交付”的界面。

核心目标：

- 首页先告诉用户当前运行是否可用
- 列表让用户能比较最近几次运行
- 详情页让用户看清缺什么、下一步做什么
- 结果页继续把 PDF 报告作为第一交付物
- 技术路径、底层文件和调试信息默认后置

本任务只产出 UI 设计与文案方案，不修改应用代码。

## 2. 设计原则

### 2.1 一个页面只服务一个主要动作

每个页面只保留一个最重要的主动作。

- 首页：生成审阅包，或导入运行结果
- 最近运行卡片：生成审阅包，或处理此运行
- 运行详情：生成审阅包，或修正缺项
- 生成前确认：生成审阅包
- 结果页：打开 PDF 报告

### 2.2 先状态，后技术细节

用户第一眼应该先看到：

- 当前是否找到运行
- 当前是否完整
- 当前能不能生成审阅包
- 当前还缺什么

技术文件路径、底层字段、候选文件和附属文件都应放入折叠区。

### 2.3 中文优先

客户可见层统一使用中文：

- 证据包文件
- 校验回执文件
- 摘要文件
- 审阅包
- PDF 报告
- 运行结果
- 运行结果收件箱

`bundle / receipt / summary` 只作为技术辅助说明，不进入第一层主视觉。

### 2.4 结果优先

结果页第一屏只回答三个问题：

- 审阅包是否生成成功
- 正式交付物在哪里
- 下一步怎么打开、复制或发送

Markdown 报告、索引文件、主文件和附属文件都放到“查看输出详情”之后。

### 2.5 帮助与反馈常驻但不抢主路径

每个主页面提供轻量帮助入口：

- 首页：查看试用步骤
- 列表：如何判断运行状态
- 详情：如何修正缺失文件
- 结果页：如何发送 PDF 报告

帮助入口是次级按钮或右上角小入口，不替代主动作。

## 3. 页面结构

### 3.1 首页：运行监测首页

第一屏信息顺序：

1. 产品状态标题：智能体运行监测
2. 当前监控来源：运行结果收件箱 / 手动导入目录
3. 最近一次运行状态：已找到 / 未找到 / 需处理
4. 主动作：生成审阅包 / 导入运行结果
5. 次级动作：查看详情 / 帮助
6. 最近运行列表摘要

首页不展示完整技术路径，不直接展示三件套英文名。

### 3.2 最近运行列表卡片

每条运行卡片展示：

- 运行编号或目录名
- 时间
- 状态摘要
- 缺失项摘要
- 主动作
- 次级动作

状态文案统一：

- 证据完整，可生成审阅包
- 缺少校验回执，需处理
- 缺少摘要文件，需处理
- 缺少证据包文件，需处理
- 审阅包已生成

### 3.3 运行详情页

第一屏信息顺序：

1. 顶部摘要：运行编号、来源、时间、当前状态
2. 证据完整性：证据包文件、校验回执文件、摘要文件
3. 当前判断：可生成审阅包 / 需处理 / 需人工复核
4. 下一步动作：生成审阅包 / 处理此运行
5. 政策检查项摘要
6. 文件详情折叠区

详情页不是调试页。完整路径默认折叠。

### 3.4 结果页

第一屏信息顺序：

1. 审阅包已生成
2. PDF 报告
3. 保存位置
4. 打开 PDF 报告
5. 复制 PDF 路径
6. 打开文件夹
7. 返回最近运行
8. 查看输出详情

Markdown 报告明确标记为“技术格式 / 中间格式”。

## 4. 帮助与失败提示

### 4.1 帮助入口

建议固定文案：

- 帮助
- 查看操作步骤
- 如何修正缺失文件
- 如何发送 PDF 报告

帮助内容只提供下一步，不解释底层实现。

### 4.2 失败提示

失败提示必须包含三部分：

- 发生了什么
- 可能原因
- 用户下一步可以做什么

示例：

```text
未找到校验回执文件
这次运行还不能直接生成审阅包。
你可以重新选择运行结果目录，或进入高级手动修正补充校验回执文件。
```

### 4.3 处理中反馈

长耗时动作必须显示处理中状态：

- 正在识别运行结果
- 正在生成审阅包
- 正在检查 PDF 报告
- 正在打开文件夹

按钮在处理中应避免重复点击。

## 5. 推荐视觉方向

### 5.1 风格

建议继续使用“深绿侧栏 + 暖白内容卡片”的方向，适合内部试点和政企场景，避免过度消费级、过度炫技。

关键词：

- 稳定
- 清楚
- 低噪音
- 状态优先
- 中文阅读友好

### 5.2 色彩角色

- 主色：深绿色，用于侧栏、主按钮、完成状态
- 背景：暖白色，降低长时间阅读疲劳
- 成功：浅绿色标签
- 警告：浅黄色标签
- 错误：浅红色标签
- 次级按钮：浅米色或低对比灰

### 5.3 布局节奏

- 左侧保留步骤导航，但不让它承担主要解释
- 右侧主内容区采用大卡片
- 主状态区高度控制在第一屏可读范围内
- 列表卡片每条只展示最少状态
- 详情页用分区卡片，不用大表格

## 7. 不做什么

本设计任务不做：

- 代码实现
- 新功能开发
- 新页面范围扩张
- Windows 适配
- 签名 / 公证
- 云端 / 账号 / 同步
- 完整策略引擎
- 大图表或统计看板
