## 5. Limitations and Conclusion

The present artifact has clear limitations. First, only one valid context is currently repo-backed. The positive path is the metadata-enrichment case used by the shipped example and demo. The paper therefore cannot claim that the same profile has already been validated across multiple contexts.

Second, the current artifact does not establish validity beyond the current repo-backed context. It provides one validator path, one valid example, three invalid examples, and one demo, but it does not demonstrate that the same object model has been confirmed across multiple frameworks, runtimes, or institutional settings. Any broader cross-setting validity language would go beyond the current evidence base.

Third, the paper does not contribute a full FDO interoperability layer. The work is situated in an FDO-based or FDO-informed context because it is object-centered and because the operation statement is organized around subject objects, references, and evidence links. But the contribution stops well short of a broader interoperability stack, registry design, or protocol implementation strategy.

Fourth, there is no deployment evidence in the current package. The artifact has a runnable path and test anchors, but it is not a field deployment study, not a performance paper, and not an operations report. The evaluation therefore cannot support claims about production robustness, scale, or external adoption.

These limits are not accidental. They follow from the paper's main design choice: closure over breadth. By keeping the profile small, the validator staged, the example boundary controlled, and the demo single-path, the artifact becomes easier to inspect and easier to critique. That does not make it a broad solution. It makes it a sharper research object.

Within that smaller boundary, the paper's conclusion is straightforward. Execution evidence for one agent-mediated operation can be represented as a bounded accountability object rather than left implicit in a larger trace surface. A minimal profile, together with a schema, a validator, controlled examples, tests, and a runnable demo, is enough to create a small inspectable closure for that claim. The contribution is therefore not a larger system layer, not richer telemetry, and not a general governance system. It is a narrow but checkable artifact for one operation in an FDO-based setting.
