# SIDS 标题选项 v1

## 偏工程

1. `面向 FDO 数据访问的最小执行证据 Profile 与校验路径`
适合什么口味的评审：喜欢明确工件边界、看重 schema 与 validator 落地的评审。

2. `用于 Agent 数据访问问责的最小执行证据 Profile、Validator 与 Demo`
适合什么口味的评审：接受“窄工件 + 可复跑”叙述、希望一眼看到实现面的评审。

3. `单次操作问责的最小可验证 Profile：来自 FDO 场景的执行证据样品`
适合什么口味的评审：偏好 artifact specimen 叙述，不要求系统级雄心的评审。

4. `Execution Evidence 不是日志：一个面向 FDO 操作问责的最小工程基线`
适合什么口味的评审：喜欢问题导向、但仍希望看到工程抓手的评审。

## 偏数据空间

5. `数据空间中 Agent 介导访问的最小执行证据 Profile`
适合什么口味的评审：更关注 data spaces 语境，希望标题先落场景再落方法的评审。

6. `FDO 数据访问中的单操作问责：一个最小可验证执行证据路径`
适合什么口味的评审：接受 FDO 术语，但不希望标题太像软件工程投稿的评审。

7. `面向 Agent-Mediated Data Visitation 的执行证据最小基线`
适合什么口味的评审：偏爱 data visitation 语言、重视对象访问语境的评审。

## 偏问责 / 验证

8. `从日志到可验证对象：FDO 场景下单操作问责的最小执行证据`
适合什么口味的评审：对“为什么不是普通日志”这个问题最敏感的评审。

9. `单操作问责的可验证边界：一个面向 FDO Agent 系统的最小证据 Profile`
适合什么口味的评审：关注 verification boundary 与 reviewer-facing artifact 的评审。

10. `把数据访问问责写成可检查对象：FDO 场景中的最小执行证据 Profile`
适合什么口味的评审：偏好“问题转换”叙述，希望标题直接显示文章立场的评审。
